# Nova RFCs

Request for Comments documents will record consequential design decisions before implementation.
Use an RFC for changes to:

- Persistent file formats
- Durability or consistency guarantees
- Public protocols and APIs
- Query semantics
- Replication, failover, and cluster behavior
- Contributor governance

An RFC should explain the problem, goals, non-goals, proposed design, alternatives, failure modes,
compatibility, observability, security, testing, rollout, and unresolved questions.

Accepted RFCs will receive a sequential number and descriptive filename, for example
`0001-segment-file-format.md`.
